# 画像格式和导出

模型依据[学习流程](learn-style.md)从全部获准的样本中归纳风格。用户确认可长期复用的规则后，把规则和合成例句整理成下面的 JSON。确认结果、依据及原稿定位留在工作区自己的学习记录中。

```json
{
  "schema_version": 1,
  "id": "team-cedar-voice",
  "display_name": "示例团队文风",
  "version": "1.0.0",
  "shared_rules": [
    {
      "when": "同一材料支持若干不同范围的判断。",
      "write": "指出材料能证明的最具体事实，再写该事实与结论之间还缺哪一环。",
      "preserve": "材料归属、证明范围及原有语气强度。",
      "exception": "读者需要先知道决定时，先给结论并紧接材料。"
    }
  ],
  "genres": [
    {
      "name": "二审答辩状",
      "rules": [
        {
          "when": "上诉人认为原判漏看了某份材料。",
          "write": "先交代原判如何审查该材料，再解释材料的证明范围。",
          "preserve": "裁判审级、原引文、页码以及原有结论的条件。",
          "exception": "原判没有记载材料时，按当次可核材料另行分析。"
        }
      ]
    }
  ],
  "examples": [
    {
      "genre": "通用",
      "before": "交接单上有钥匙签收人签字，签字表明收到钥匙，该单不能证明场地已经复验合格。",
      "after": "交接单上的签字只证明收到了钥匙，该单仍不足以证明场地已经复验合格。",
      "explanation": "先交代签字可以证明的事项，再标示结论所缺的证据。"
    }
  ]
}
```

- 字段名按上例填写。各文本字段使用一行纯文本。用 `id` 作为 Skill 目录名，使用 1–64 个小写 ASCII 字母、数字和单个连字符。版本号使用 `1.0.0` 这样的三段数字。
- 共通规则和文体规则合计至少有一条。某种写法只有单一文体支持时，可令 `shared_rules` 为 `[]`，把规则放在该文体。文体名须唯一。
- `examples` 可填 `[]`。示例中的文体填已声明的名称或 `通用`。例句用合成内容，前后保持同一事实、立场、请求和限定。
- JSON 输入只包含需要导出的抽象写法。每条规则的原稿、来源位置、确认决定和回撤记录留在学习工作区。脚本核查结构与格式，规则是否忠实于样本、例句是否含有历史案件内容由审阅者核对。

用 Python 3.9 或更新版本，在此 Skill 根目录执行：

```bash
python3 scripts/export_voice.py approved-profile.json generated
```

工具在 `generated/<id>/` 生成 `SKILL.md`、`references/voice-rules.md` 及可选的 `references/examples.md`。把生成目录作为一套独立 Skill 加载。使用时只需该目录及本次写作材料。

更新画像时保存完整的新版本 JSON，并另用一个父目录导出，便于对照和回撤。例如当前画像为 `generated/v1/team-cedar-voice/`，下一版可导出到 `generated/v2/`。工具拒绝覆盖已有 Skill。在 Codex 里切换时选择当前要用的那一版目录。
